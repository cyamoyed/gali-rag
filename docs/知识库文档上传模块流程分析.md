# 知识库文档上传模块流程分析


## 一、完整后端流程

### 1.1 流程总览

```
前端拖拽/选择文件
  │
  ▼
POST /api/v1/knowledge-bases/{kb_id}/documents/upload  (multipart/form-data)
  │
  ▼
┌─ chat.py:upload_documents() ─────────────────────────────────────┐
│  1. 校验知识库是否存在 (kb_service.get)                            │
│  2. 遍历每个文件:                                                 │
│     a. validate_file(filename) → 检查扩展名是否支持               │
│     b. await file.read() → 读取文件内容到内存                     │
│     c. 检查文件是否为空                                           │
│     d. 检查文件大小是否超限 (MAX_UPLOAD_SIZE_MB=50MB)             │
│     e. validate_file(filename, content) → magic bytes 校验        │
│        (PDF检查%PDF头, DOCX检查PK\x03\x04头)                     │
│     f. doc_service.save_upload() → UUID重命名写入磁盘             │
│        路径: data/uploads/{uuid4_hex}.ext                         │
│     g. doc_service.create_record() → 写入DB记录                   │
│        Document表: status="pending", kb_id, filename, file_path  │
│     h. background_tasks.add_task(_process_doc_background, doc.id) │
│        → 注册后台异步任务                                         │
│  3. 返回响应: {"code":200, "message":"上传成功，文档正在后台处理"}   │
└──────────────────────────────────────────────────────────────────┘
  │ (异步)
  ▼
┌─ _process_doc_background(doc_id) ────────────────────────────────┐
│  创建独立DB会话 (SessionLocal)                                    │
│  调用 doc_service.process_document(bg_db, doc_id)                 │
│  异常兜底: 更新doc.status="failed"                                │
└──────────────────────────────────────────────────────────────────┘
  │
  ▼
┌─ doc_service.process_document() ─────────────────────────────────┐
│                                                                   │
│  Step 1: 状态更新                                                  │
│    doc.status = "processing" → db.commit()                        │
│                                                                   │
│  Step 2: 文档解析 (document_parser.parse_document)                 │
│    根据扩展名选择解析器:                                            │
│    .pdf  → pypdf.PdfReader 逐页提取文本                            │
│    .docx → python-docx 提取段落文本                                │
│    .md   → markdown→HTML→正则去标签→纯文本                         │
│    .txt  → 直接读取(UTF-8/GBK/GB2312/Latin-1 编码回退)            │
│                                                                   │
│  Step 3: 文本清洗 (document_parser.clean_text)                     │
│    合并多余空行(\n{3,}→\n\n)                                       │
│    合并多余空格([ \t]{2,}→" ")                                     │
│    去除控制字符(\x00-\x08等)                                        │
│    检查清洗后内容是否过短(<2字符则报错)                              │
│                                                                   │
│  Step 4: 文本切片 (text_splitter.split_text)                       │
│    参数来自知识库配置: chunk_size, chunk_overlap, semantic          │
│    参数校验: chunk_size∈[100,10000], overlap<chunk_size-10         │
│                                                                   │
│    固定长度模式 (默认):                                             │
│      langchain RecursiveCharacterTextSplitter                      │
│      分隔符优先级: \n\n → \n → 。→ . → ！→ ! → ？→ ? → ；→ ; → 空格│
│                                                                   │
│    语义切片模式 (semantic=True):                                    │
│      先按Markdown标题(#~######)拆分章节                             │
│      无标题则按段落(双换行)或句子拆分                                │
│      超长章节再做固定长度二次切分                                    │
│                                                                   │
│  Step 5: LLM合并 (可选, llm_chunk_enabled=True)                   │
│    相邻小切片(合并后<600字符)合并为一个切片                          │
│    合并失败则静默回退使用原始切片                                    │
│                                                                   │
│  Step 6: 过滤空切片                                                │
│    chunks = [c for c in chunks if c.strip()]                      │
│                                                                   │
│  Step 7: 写入DocumentChunk表                                       │
│    删除该文档的旧切片记录(支持重处理)                                │
│    逐条创建: doc_id, chunk_index, content, token_count(tiktoken)  │
│    db.flush() → 获取chunk DB id                                   │
│                                                                   │
│  Step 8: 向量化 (embedding_client.embed)                           │
│    根据知识库绑定的embedding模型或全局配置选择provider               │
│    支持 Ollama (/api/embed) 和 OpenAI兼容 (/embeddings)            │
│    分批发送: 每批100条, 3次指数退避重试                              │
│    返回 List[List[float]] 向量                                     │
│                                                                   │
│  Step 9: 写入ChromaDB向量库                                        │
│    collection名: kb.chroma_collection (创建知识库时生成)            │
│    每条记录:                                                       │
│      id: "doc{doc_id}_chunk{i}"                                   │
│      document: 切片文本内容                                        │
│      embedding: 向量浮点数                                         │
│      metadata: {doc_id, doc_name, chunk_db_id, chunk_index, kb_id}│
│    批量写入: 每500条一批                                           │
│                                                                   │
│  Step 10: 刷新BM25缓存                                             │
│    bm25_cache.invalidate(collection_name)                          │
│    下次检索时会重建BM25索引                                         │
│                                                                   │
│  Step 11: 更新最终状态                                              │
│    doc.chunk_count = len(chunks)                                   │
│    doc.status = "completed"                                        │
│    doc.error_message = ""                                          │
│    db.commit()                                                     │
│                                                                   │
│  异常处理:                                                         │
│    db.rollback() → 重新查询doc → status="failed"                   │
│    error_message = str(e)[:1000]                                   │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 关键数据表流转

```
Document表状态变化:  pending → processing → completed/failed
                                                    ↑
                                              (异常时回滚后更新)

DocumentChunk表:     处理成功后逐条写入, 每条含content+token_count
                     重处理时先DELETE旧记录再重建

ChromaDB向量集合:    处理成功后批量写入, 含向量+元数据
                     重处理时先按doc_id删除旧向量再重建

BM25缓存:           处理成功后invalidate, 下次检索自动重建
```

### 1.3 前端感知处理结果

前端上传后立即收到 `{status: "pending"}` 响应。之后通过轮询 `GET /api/v1/knowledge-bases/{kb_id}/documents` 获取文档列表，检查每条文档的 `status` 字段变为 `completed` 或 `failed`（`failed` 时可查看 `error_message`）。

## 二、涉及的核心文件

| 文件 | 职责 |
|------|------|
| `app/api/v1/chat.py` | API路由层，文档上传/删除/重处理等端点 |
| `app/services/doc_service.py` | 文档服务层，处理全流程编排 |
| `app/utils/document_parser.py` | 文档解析，多格式内容提取与文本清洗 |
| `app/utils/text_splitter.py` | 文本切片，固定长度/语义两种策略 |
| `app/rag/embedding_client.py` | Embedding客户端，支持Ollama和OpenAI兼容格式 |
| `app/rag/vector_store.py` | ChromaDB向量存储管理 |
| `app/rag/multi_retriever.py` | 多路召回(稠密向量+BM25)，含BM25缓存 |
| `app/models/models.py` | SQLAlchemy ORM模型定义 |
| `app/core/config.py` | 全局配置项 |
| `app/utils/token_counter.py` | Token计数工具(tiktoken) |

## 四、配置项参考

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `MAX_UPLOAD_SIZE_MB` | 50 | 单文件上传大小限制(MB) |
| `CHUNK_SIZE` | 500 | 默认切片大小(字符数) |
| `CHUNK_OVERLAP` | 100 | 默认切片重叠(字符数) |
| `SEMANTIC_CHUNK_ENABLED` | False | 是否启用语义切片 |
| `LLM_CHUNK_ENABLED` | False | 是否启用LLM合并切片 |
| `EMBEDDING_PROVIDER` | ollama | Embedding服务提供商 |
| `EMBEDDING_MODEL` | nomic-embed-text | 默认Embedding模型 |
| `HNSW_M` | 16 | HNSW索引M参数 |
| `HNSW_EF_CONSTRUCTION` | 200 | HNSW构建ef参数 |
| `HNSW_EF_SEARCH` | 100 | HNSW搜索ef参数 |

## 五、API端点参考

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/knowledge-bases/{kb_id}/documents/upload` | 上传文档(multipart/form-data) |
| GET | `/api/v1/knowledge-bases/{kb_id}/documents` | 查询文档列表(分页) |
| DELETE | `/api/v1/documents/{doc_id}` | 删除单个文档 |
| POST | `/api/v1/documents/batch-delete` | 批量删除文档 |
| POST | `/api/v1/documents/{doc_id}/reprocess` | 重新处理文档 |
| POST | `/api/v1/documents/{doc_id}/summary` | 生成文档摘要(LLM) |
| GET | `/api/v1/documents/{doc_id}/chunks` | 获取文档切片列表(分页) |
| PUT | `/api/v1/knowledge-bases/{kb_id}/chunk-config` | 更新切片参数配置 |
| POST | `/api/v1/knowledge-bases/{kb_id}/clean-vectors` | 清理孤立向量 |
| POST | `/api/v1/knowledge-bases/{kb_id}/clear-vectors` | 清空整个向量库 |
| POST | `/api/v1/knowledge-bases/{kb_id}/hit-test` | 命中测试(仅检索不调LLM) |
